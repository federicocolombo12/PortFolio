Embedded firmware and hardware architecture for a screenless book-lending Smart Locker powered by **ESP32 (C++ / Arduino)**, **Firebase Realtime Database**, I2S digital audio, ultrasonic presence sensing, and NeoPixel LED rings. ([Project Report](https://www.canva.com/design/DAHAFhC8tz0/KKv57OQ4PoPhY5P6FZZRXQ/edit?utm_content=DAHAFhC8tz0&utm_campaign=designshare&utm_medium=link2&utm_source=sharebutton))

### 1. Screenless DTMF Audio Handshake (I2S + Goertzel)

<video src="https://federicocolombo12.github.io/PortFolio/projects/Phygital_Smart_Locker/IMG_5505.mp4" autoPlay loop muted playsInline style={{float: 'left', width: '40%', margin: '0 1rem 1rem 0', borderRadius: '12px'}}></video>

To avoid installing physical keypads or screens on the cabinet, authentication uses smartphone-emitted **DTMF audio tones**:
- Samples a digital `INMP441` microphone at `16 kHz` over **I2S** without blocking the main loop.
- Decodes dual-tone frequencies in real time on the ESP32 using a custom **Goertzel algorithm** with temporal debounce and anti-repetition filters against room noise.
- Validates dynamic 4-digit Cloud session tokens wrapped with a `#` start frame and strict timeout guards.

### 2. Anti-Cheat State Machine & Cloud Sync

Instead of simple open/close toggles, each bay runs a non-blocking **Finite State Machine** reading the lock relay, door microswitch, and `HC-SR04` ultrasonic sensor: if a user requests a return, opens an empty bay, and closes the door without inserting a book, the ESP32 detects the state mismatch and **automatically reopens the compartment** while flagging Firebase (`isClosed`, `hasBook`).

### 3. Screenless Visual Feedback & Hardware Hardening

<video src="https://federicocolombo12.github.io/PortFolio/projects/Phygital_Smart_Locker/WhatsApp_Video_2026-03-05_at_15.23.23.mp4" autoPlay loop muted playsInline style={{float: 'right', width: '30%', margin: '0 0 1rem 1rem', borderRadius: '12px'}}></video>

- **NeoPixel Ring UX:** Drives non-blocking circular yellow scan progress during the 3s ultrasonic check and green/red status signals on completion.
- **Watchdog & Power Isolation:** Eliminated `delay()` calls across I2S sampling, Firebase WebSockets, and LEDs to prevent ESP32 Watchdog resets, and physically isolated `5V` inductive lock coils from the `3.3V` sensor/audio rails to stop brownout kernel panics.
